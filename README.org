#+title:   list-mode
#+author:  Daniel Nagy
#+options: toc:2
#+startup: overview

A base major mode for read-only Emacs tables whose every row is an object.

The mode derives from [[https://www.gnu.org/software/emacs/manual/html_node/elisp/Tabulated-List-Mode.html][tabulated list mode]], so a table keeps clickable column headers, sorting, column widening and point keeping across a reprint.
A derived mode hands the buffer a list of row structs, and this package renders the table from them.
A row expands into child rows, to any depth, and a mode may load those child rows in the background.
A row whose data went away answers so, and the table dims it without refreshing itself.

* Installation

The package needs Emacs 31.1 and nothing else.
Two optional libraries unlock an extra file each: evil for the evil layer, and [[https://github.com/nagy/emacs-map-extras][map-extras]] for the frame, window and buffer demo.

#+begin_src emacs-lisp
(require 'list-mode)
#+end_src

* Defining a mode

A derived mode declares its columns, calls ~list-mode-init~, and prints through ~list-mode-set-rows~.

#+begin_src emacs-lisp
(cl-defstruct (bug-row (:include list-row))
  "One bug of the tracker."
  id title state)

(cl-defmethod list-row-cells ((row bug-row) _columns)
  "Return the cells of ROW."
  (vector (format "#%d" (bug-row-id row))
          (bug-row-title row)
          (bug-row-state row)))

(define-derived-mode bug-list-mode list-mode "Bugs"
  "Show the bugs of the tracker."
  (setq-local list-mode-columns
              [("ID" 8 t) ("Title" 40 t) ("State" 0 t)])
  (setq-local list-mode-default-sort-key '("ID"))
  (setq-local list-mode-refresh-function #'bug-list--fetch)
  (list-mode-init))

(defun bug-list (bugs)
  "Show BUGS in a new table."
  (interactive)
  (let ((buffer (get-buffer-create "*Bugs*")))
    (with-current-buffer buffer
      (bug-list-mode)
      (list-mode-set-rows bugs)
      (pop-to-buffer buffer))))
#+end_src

* Rows

A row is a ~cl-defstruct~ that includes ~list-row~, so Emacs dispatches ~cl-defmethod~ on its type.
A struct, not a class, because a record compares with ~equal~, and because a row is plain data that a mode builds and rebuilds.

| Slot         | Meaning                                                                   |
|--------------+---------------------------------------------------------------------------|
| ~key~        | Identity of the row in its table, compared with ~equal~                    |
| ~expandable~ | Non-nil when the row can show child rows                                  |
| ~expanded~   | Non-nil when the table shows them                                         |
| ~child-rows~ | ~nil~ for an unknown answer, ~:pending~ for a fetch in flight, or a list   |
| ~cell-faces~ | Alist of a column name to a face that paints that cell for this row       |

The key is the identity of the printed line, so a refresh that builds new row objects keeps point on the same row.
Keep a key stable across a refresh and unique in one table.

Five generic functions define what a row does.

- ~list-row-cells~ returns the cells of the row as a vector, for the column vector that it receives.
- ~list-row-children~ returns the child rows, or ~:pending~ after starting a fetch, or ~nil~ for a leaf.
- ~list-row-expandable-p~ decides whether a toggle reaches the row.
- ~list-row-visit~ opens what the row stands for, for the RET key.
- ~list-row-stale-p~ says whether the data behind the row went away.

A key must stay unique in one table, and it must stay the same across a refresh.
A repeated key still prints each line with its own row, and the table warns about it, but point keeping and the key path name the first row.

The first cell must be a string, because the base puts the indentation of the depth in front of it.
A cell after the first takes any value that ~tabulated-list-print-entry~ accepts, such as a string, a cons of a label and properties, or an image.

A face is declared, never painted: the column carries a ~:face~, and a row that needs another face for one cell names the column in its ~cell-faces~ slot.
The base paints the cell text, so a mode declares nothing twice and calls ~propertize~ nowhere.

#+begin_src emacs-lisp
(setq-local list-mode-columns
            [("ID" 8 t) ("Title" 40 t)
             ("State" 0 t :face font-lock-keyword-face)])

;; a row that overrides the face of one cell
(setf (list-row-cell-faces row) '(("Title" . font-lock-warning-face)))
#+end_src

The base paints a string cell and a cons of text and button properties, and it leaves the indentation of the first cell plain.
A row answers plain text for ~list-row-cells~ all the same, because the fitting and the text sorter read that text.
A declaration that names no column or no face warns once per table, so a typo never leaves the table silently plain.

* Columns

~list-mode-columns~ is a vector in the shape of ~tabulated-list-format~: one ~(NAME WIDTH SORTER . PROPS)~ list per column.

- ~WIDTH~ is the width that the column asks for, which the fitting may shrink to its header when the window is narrow, and ~0~ makes the column take the space that the others leave.
- ~SORTER~ is ~t~ for a text comparison of that column, a predicate of two rows, or ~nil~ for a column without sorting.
  A function receives rows, not the entries that ~tabulated-list-format~ documents, because the table sorts its tree before it builds the entries.
- ~PROPS~ takes the properties of the list library, such as ~:right-align~ and ~:pad-right~, and ~:face~, the face that paints every row of the column.

The columns fit the window on every print.
The fitting measures the header and the printed cells, starts from the declared widths, gives a flexible column the space that is left, and shrinks the widest columns together when the total overflows.
A flexible column keeps room for its widest cell, because the last column of the table is never truncated, so a table whose cells fit the window fits it whole.
A resize refits the table.
A manual widening through ~{~ or ~}~ is a width delta on top of the fitting, so it survives a resize and a flexible column stays flexible.
Set the option ~list-mode-fit-columns~ to ~nil~ to keep the declared widths.

* Map rows

~list-mode-map.el~ adds a row type whose cells come from the [[https://www.gnu.org/software/emacs/manual/html_node/elisp/Mapping-Functions.html][map.el]] protocol, so a table over alists, plists or hash tables needs no row type of its own.
A column names its map key with ~:key~ and may print the value with ~:formatter~.

#+begin_src emacs-lisp
(setq-local list-mode-columns
            [("Name" 12 t :key name)
             ("Size" 6 t :key size)])
(list-mode-init)
(list-mode-set-rows
 (mapcar (lambda (alist)
           (list-map-row-create :key (map-elt alist 'name) :object alist))
         alists))
#+end_src

The adapter prints text: a column without a ~:key~, and a key that the map does not hold, answer an empty cell, and a value that is not text passes through the formatter first.
The first cell stays a string, because the base puts the indentation in front of it.
~list-map-row-cell-text~ is the default formatter, and ~list-map-row-elt~ reads one column value for a predicate sorter.

With [[https://github.com/nagy/emacs-map-extras][map-extras]] on the load path, the same row wraps a window, a buffer, a frame or a process:

#+begin_src emacs-lisp
(setq-local list-mode-columns
            [("Buffer" 20 t :key buffer
              :formatter (lambda (buffer) (buffer-name buffer)))
             ("Start" 8 t :key start)])
(list-mode-set-rows
 (mapcar (lambda (window)
           (list-map-row-create :key window :object window))
         (window-list)))
#+end_src

A live object changes under its row while two rows that wrap it still compare ~equal~, so such a table refreshes with ~list-mode-reprint~ and not with ~list-mode-set-rows~, which would find no change.
A plain map row is a leaf.
~list-map-tree-row~ adds the one slot that a tree needs, a maker that answers the child rows of a row.
A child key must stay unique in the whole table, so a maker that wraps one object at two places, as two windows that show one buffer do, builds its child keys from the key of the parent.

* Demo

~M-x list-demo~ prints a map-backed table of the live frames, their windows and the buffer of each window, with every cell read through ~map-elt~.
It needs ~map-extras~ on the load path, because builtin ~map.el~ covers no frame, window or buffer; the package itself does not depend on it.
~TAB~ expands a frame into its windows and a window into the buffer that it displays, ~RET~ selects the frame or the window or shows the buffer, and ~g~ reads the tree again.
A frame, a window or a buffer that dies leaves a stale row, which the table dims until a refresh reads the tree again; ~auto-revert-mode~ in the table buffer does that for you.
The demo answers ~list-row-stale-p~ with ~frame-live-p~, ~window-live-p~ and ~buffer-live-p~, so the row of a killed window still prints its cells but refuses to expand.

* Expansion

~TAB~ toggles the row at point, and a child row expands further, to any depth.
The child rows sit below their parent, indented by ~list-mode-indent~ spaces per level.

The row loads its child rows the first time the table prints it expanded.
A row whose child rows arrive from a network answer ~:pending~ and calls ~list-mode-set-children~ from its callback.
The table shows a placeholder row while the fetch runs.

#+begin_src emacs-lisp
(cl-defmethod list-row-children ((row bug-row))
  "Fetch the child rows of ROW from the tracker."
  (bug-api-fetch-comments
   (bug-row-id row)
   (lambda (comments)
     (list-mode-set-children row (bug-row--comment-rows comments)))
   (lambda (_error)
     (list-mode-set-children row nil)))
  :pending)
#+end_src

A fetch that answers nothing turns the row into a leaf, so a toggle never retries it.
~list-mode-forget-children~ drops a cached answer, so the next expanded print reads it again.

The callback may run in any buffer, such as the buffer of a network process: ~list-mode-set-children~ finds the table that prints the row.
An answer that arrives after a ~TAB~ collapsed the row leaves the row closed.

* Keys

| Key                 | Command                    |
|---------------------+----------------------------|
| ~TAB~               | ~list-mode-toggle-row~     |
| ~RET~               | ~list-mode-visit-row~      |
| ~S~                 | ~list-mode-sort~           |
| ~{~ and ~}~         | ~list-mode-narrow-column~ and ~list-mode-widen-column~ |
| ~<mouse-2>~         | ~list-mode-mouse-visit~    |
| ~<double-mouse-1>~  | ~list-mode-mouse-toggle~   |
| ~g~                 | ~revert-buffer~            |

A click on a column header sorts by that column, and a second click flips the direction.
The numeric prefix of ~list-mode-sort~ names the column from 0.
~list-mode-set-sort~ sets the sort state from Lisp, and ~list-mode-sort-key~ reads it.

* Refresh

A mode sets ~list-mode-refresh-function~ to a function that reads new rows and calls ~list-mode-set-rows~.
~revert-buffer~ reaches it, so ~g~ and ~auto-revert-mode~ work.

~list-mode-set-rows~ prints nothing when the new list compares ~equal~ to the installed one, so point, the window start and every open row survive a refresh that found no change.
Any other list keeps the expansion state of a row that shares its key path, at any depth and even below a collapsed ancestor, and drops the cached child rows, because the new row may print different children.

* Staleness

A row answers ~list-row-stale-p~ when the data behind it is out of date.
A row that wraps a live object answers whether the object still exists, and a row that reads a file answers whether the file changed.

#+begin_src emacs-lisp
(cl-defmethod list-row-stale-p ((row bug-row))
  "Return non-nil when the bug of ROW was deleted."
  (not (bug-api-exists-p (bug-row-id row))))
#+end_src

The table never refreshes itself.
It reports the answer instead: ~list-mode-mark-stale-rows~ paints the printed line of a stale row in ~list-row-stale~, the base refuses to expand the row, and ~buffer-stale-function~ answers from the printed rows, so ~auto-revert-mode~ reverts the table when a printed row goes stale.
~TAB~ and ~RET~ on a stale row signal a ~user-error~ that names ~g~.

~list-mode-mark-stale-rows~ paints the rows that a window displays, and the buffer-local ~pre-redisplay-functions~ hook calls it for every window that is about to show the table.
A data change reports no window event, and a redisplay is the moment when the table can show it, so a table that nothing refreshes still says which of its rows went out of date.
The mark is an overlay over the cells of the printed line, not a change to the cell text, so it keeps the indentation plain and evaporates when a reprint erases the line.

The mark pass runs on every redisplay of a table window, so ~list-row-stale-p~ must stay cheap.
A row whose test costs a network read or a file stat leaves the method at nil, and the table sets ~list-mode-stale-function~ instead.
That function answers ~buffer-stale-function~ for the whole table, which keeps ~auto-revert-mode~ in charge of the refresh.

A refresh keeps point through the row key, and a row that left the table leaves point on the nearest printed ancestor.
A revert records the stale keys that it asked for, and ~buffer-stale-function~ answers nil while the printed rows hold the same stale keys, so a refresh that cannot clear the staleness does not reprint the table on every poll.
A changed set of stale rows asks again.

~auto-revert-mode~ polls a table every ~auto-revert-interval~ seconds.
~global-auto-revert-mode~ covers a table only while ~global-auto-revert-non-file-buffers~ is non-nil, because a table visits no file, so turn on ~auto-revert-mode~ in the table buffer or set that variable.

* Reading the table

These helpers serve a bookmark record, an export or a command of the derived mode.

| Function                        | Answer                                           |
|---------------------------------+--------------------------------------------------|
| ~list-mode-row-at-point~        | The row object of the printed line               |
| ~list-mode-key-at-point~        | Its key                                          |
| ~list-mode-key-path-at-point~   | The list of keys from a top-level row down to it |
| ~list-mode-depth-at-point~      | Its depth                                        |
| ~list-mode-parent-row-at-point~ | The row that holds it                            |
| ~list-mode-visible-rows~        | Every printed row as a ~(ROW . DEPTH)~ cons      |
| ~list-mode-key-path~            | The key path of one row object                   |
| ~list-mode-find-row~            | The row of a key among the loaded rows           |
| ~list-mode-region-rows~         | The rows that the active region covers           |
| ~list-mode-region-p~            | Non-nil when the active region covers a row      |
| ~list-mode-stale-p~             | Non-nil when a printed row is stale              |

A region answers the rows that it covers, in display order.
Both ends join, so the row at point joins even when the region ends at its line start, and a line motion grows the region one row per step.
A row object joins once, even when the table prints it on more than one line, and the placeholder line of a running fetch names the row that owns the fetch.
The function reads point and mark, so it reads a plain Emacs region and the visual selection of the evil layer alike.
A command of the evil layer carries ~:exclude-newline~, because the expanded range of a linewise selection ends on the line below the selection.

* Options and faces

| Option                  | Default | Meaning                                       |
|-------------------------+---------+-----------------------------------------------|
| ~list-mode-indent~      | ~2~     | Spaces that one level adds to the first cell  |
| ~list-mode-fit-columns~ | ~t~     | Fit the columns to the window                 |

The face ~list-row-placeholder~ colors the row that stands in while child rows load.

* Evil layer

~list-mode-evil.el~ is an optional layer, and the package does not depend on evil.
The entry library loads the layer once evil loads, so both lines below are optional:

#+begin_src emacs-lisp
(require 'list-mode-evil)
(list-mode-evil-mode 1)
#+end_src

While ~list-mode-evil-auto-enable~ holds, which is the default, ~list-mode-evil-auto-setup~ loads the layer when evil loads and installs the bindings in every list table, including the tables that are already open.
Set the option to ~nil~ before evil loads to keep the bindings off until a call to ~list-mode-evil-mode~.
In the normal state it binds ~TAB~ to the toggle, ~RET~ to the visit, ~S~ to the sort, and ~zo~, ~zc~, ~za~, ~zR~ and ~zM~ to the expansion commands.
The evil motions keep their meaning.
